# Theme library: saved themes, named themes and project frames

## Context and problem

The Theme Lab could build a design and try it as GigglyBits Dark (Lab), but nothing kept it. The user wanted to name a design, save it, delete it, and use it from any VS Code window or project, such as a 'copirate' theme in one workspace and a 'webscreenfw1' theme in another. VS Code only lists color themes an installed extension declares, so a design made at run time cannot appear in the theme picker through GigglyBits' own manifest.

## Decision

- **Saved themes live in the user setting `gigglybits.library`**, application-scoped, so every window reads the same list and Settings Sync carries it. A saved theme is `{ id, name, slot, design, savedAt }`, where `design` is everything the Lab holds: the palette mode and the settings that made it, the resolved colors, the Editor accent and surfaces, the Frame, color edits, and the Roles step's `syntax`, `depth` and `text` when they differ from their defaults (`[0, 1, 2, 3, 4]`, 1 and `standard`). A design without them builds as it did before they existed; `parseDesign` keeps them only when valid, and `slotSettings` and `everywhereSettings` pass them to the builder's `chrome`. `design.syntaxSet` names the syntax set its code colors come from, when it uses one (below). `slot` is the retired slot (1 to 12) a theme saved before 2026-11-10 was bound to, or null; it is read only to migrate settings. A `groups` field from the retired style groups is ignored when read.
- **Every saved theme is a named theme in a generated extension (2026-11-10).** GigglyBits builds a theme-only extension, GigglyBits Saved Themes (`EdgeInformation.gigglybits-saved-themes`), from the library at run time and installs it with `workbench.extensions.installExtension`. Each saved theme is one theme file labelled `GigglyBits: <name>`, built with the everywhere colors below; the label is also the theme's `workbench.colorTheme` value and its settings scope, which works because saved themes have no rename. There is no limit on saved themes or themes in use. A name containing `[`, `]` or `*` is refused, since settings scopes treat those characters specially; `themeLabel` still removes them from older names. The generated extension declares `extensionDependencies` on GigglyBits, so uninstalling or disabling GigglyBits offers to uninstall or disable it too.
- **Measured before building on it** (VS Code 1.145.3, 2026-11-11, `.copirate/working/research/named-themes-probe.md`): an install takes well under a second and lists its themes without a reload, in every open window; it survives a reload and a full restart; a folder-scoped `[GigglyBits: <name>]` block applies over the theme file; deleting a theme takes it out of the picker, though a window showing it keeps its colors until it reloads; and the theme a window shows keeps its old colors after a reinstall until `workbench.colorTheme` changes. So after an install, GigglyBits sets the level that chooses the installing window's theme to Default Dark Modern and back. Other windows are not repainted (the user declined that, 2026-11-11).
- **Syntax sets replace style groups (2026-11-07).** Style groups mapped a widget family's colors to roles drawn from each theme's palette, so they could not keep code colors the same across themes. A syntax set `{ id, name, colors, isDefault, savedAt }` in the user setting `gigglybits.syntaxSets` holds one fixed `#rrggbb` per kind of code (keyword, function, string, type, number, comment, tag, attribute, variable, property, constant, operator, regex). A saved theme names its set by id; its theme file is built with that set's colors, each lifted to 4.5:1 keeping its hue, so changing a set rebuilds every theme on it. A theme on no set builds exactly as before. `gigglybits.groups` is undeclared since 0.1.1, the first Marketplace release, and unread.
- **Start set from fills an unsaved draft, never a stored set (2026-11-07).** The Syntax family's Start set from row offers three starter sources, one group at a time, each starter a chip that draws a few lines of code in its colors as a theme would draw them: the user's installed dark (`vs-dark`) themes, read from their extensions' theme files and mapped onto the thirteen kinds by the most specific matching TextMate scope, leaving out GigglyBits' own and the generated extension's; well-known dark schemes bundled as credited data (`SYNTAX_SCHEMES`: Dracula, Nord, Solarized Dark, Gruvbox (dark), One Dark, Tokyo Night, Catppuccin Mocha, each permissively licensed); and the Quiet and Harmony recipes worked out from the design's own palette and frame. A pick makes a draft held in the page only, outside the saved Lab state: nothing writes `gigglybits.syntaxSets`, saves the Lab state or sends a Try until Save New Set, which stores the draft's colors as a new set. A starter never loads into an existing set, so it cannot recolor the themes on one.
- **Use everywhere applies a theme's Editor colors; the frame belongs to the project.** Decided by the user during the 2026-11-04 live check: a frame applied to every window would defeat having differently colored workspaces. A theme file carries the theme with a Dark frame. Use in this project also writes the theme's frame keys into the folder's settings under `[GigglyBits: <name>]`, which wins over the theme file key by key.
- **Settings move off the retired slots at start-up.** When GigglyBits starts with a globalStorage path, it syncs the generated extension, then removes the `[GigglyBits Theme <n>]` blocks from the user color and token settings (writing `slot-blocks-backup-<time>.json` to globalStorage first) and moves a user theme naming a slot to the label of the saved theme that holds it; a slot no saved theme holds keeps its setting, and nothing moves while the library is empty. Each folder moves the same way when it opens. Settings Sync carries the moved user settings to other machines, where an older GigglyBits cannot show the named themes; accepted, and the CHANGELOG says to update every machine.
- **Every save builds on the settings files on disk**, not on the window's configuration. A window that had been open since before another window's save wrote back the older values once in the live check.

Rejected: applying the frame everywhere (it erases the difference between projects). Superseded on 2026-11-10: the 12 fixed slots, `GigglyBits Theme 1` to `GigglyBits Theme 12`, shipped as placeholder theme files with each saved theme's colors written to user settings under its slot's label. They capped themes in use at 12, filled user settings with about 21 KB per slot, and showed placeholder names in the picker; the generated extension replaced them.

## Architecture

- `src/themeLibrary.ts` holds every decision with no `vscode` import: `parseLibrary`, `saveTheme` (a trimmed, case-insensitive name match updates in place; a new theme gets no slot; a name with `[`, `]` or `*` throws), `deleteTheme`, `slotSettings`, `everywhereSettings`, `themeLabel`, `companionTheme`, `companionPackage` (manifest, one theme file per saved theme, and a SHA-256 of those files that the installer compares), `userSlotMigration`, `projectFrame`, `withProjectFrame`, `projectColors`, `projectFrameRefresh`, `settingsFilesFor`, `freshestSetting`, and for syntax sets `parseSyntaxSets`, `saveSyntaxSet`, `setDefaultSyntaxSet`, `deleteSyntaxSet`, `themesUsingSyntaxSet` and `syntaxColorsFor`. `everywhereSettings`, `companionTheme` and `companionPackage` take the syntax sets and resolve each theme's set; `projectFrame` passes none, since a set never touches the frame.
- `src/vsix.ts` writes the generated extension's VSIX: a zip of stored entries holding `[Content_Types].xml`, `extension.vsixmanifest`, `extension/package.json`, the theme files, a README, and GigglyBits' own `media/icon.png` as its icon (declared as the package's icon and details assets, as vsce does), so the two extensions look alike in the Extensions view. The content hash covers the README and icon, so an install made before them is replaced on the next start.
- `src/companionThemes.ts` (`CompanionThemes.sync`) installs, skips (same content hash), updates (patch version plus one) or uninstalls (empty library) the generated extension, then repaints the installing window. Calls run one at a time, and only the latest waiting call runs.
- `src/themeLibraryController.ts` does the VS Code side: settings writes, the delete modal, Use in this project (which replaces a folder's old per-folder color with the theme's frame) and Use everywhere, **GigglyBits: Choose Theme**, syntax set save, default and delete (a delete of a set in use asks in a modal), each followed by a sync, and the start-up migration above. Each window refreshes its folder's frame block and theme at start-up and when `gigglybits.library` changes.
- `media/themeBuilder.js` takes a set's colors as `chrome.syntaxColors` (`cleanChrome` keeps them only when every `SYNTAX_SET_KEYS` key is a `#rrggbb`) and draws the code roles and token rules from them, adding `SET_RULES` after today's six. The Lab's step 4 Syntax family chooses From this palette or a set, edits the set's colors, saves the drawn colors as a new set, and makes a set the default for new designs. `LEGACY_SLOT_COUNT` and `slotLabel(n)` remain for migration.
- `scripts/build-themes.js` writes only the Lab theme from its base palette `BASE` and deletes any slot file an older build wrote; the Lab theme is the only theme GigglyBits itself contributes.
- The Lab's Start step has two tabs, Wheel and Saved. The Saved tab lists saved themes one line each by name with Load, and a chevron that shows Use in this project (only with a folder open), Use everywhere and Delete; Enter on a line loads it. A saved theme of pasted colors still loads and saves as pasted, though the Lab no longer takes pasted colors. The palette Catalog (Include, Maybe and Exclude, `palettes/catalog.json`) is retired: saved themes replace it.
- The step 6 bar says "Saved as" the name once a `library` message holds a theme of that name, and warns "Overwrites" while Name matches another saved theme, trimmed and in any letter case (the same match `saveTheme` uses).

## Settings written

| Setting | Level | Content |
|---|---|---|
| `gigglybits.library` | user (default profile file) | the saved themes |
| `gigglybits.syntaxSets` | user (default profile file) | the syntax sets |
| `workbench.colorCustomizations` `[GigglyBits: <name>]` | folder | the theme's 31 frame keys, the six tab and split lines included, with any old per-folder color and any other GigglyBits frame block removed |
| `workbench.colorTheme` | folder or user | the saved theme's `GigglyBits: <name>` label |
| `workbench.colorCustomizations`, `editor.tokenColorCustomizations` | user | start-up migration only: the `[GigglyBits Theme <n>]` blocks removed |

The generated extension and its VSIX (`gigglybits-saved-themes.vsix`) and the migration backup live in GigglyBits' globalStorage folder, not in settings.

## Key interfaces

- Webview to host: `saveTheme { name, design }`, `useTheme { id, where: 'project' | 'everywhere' }`, `deleteTheme { id }`, `saveSyntaxSet { id?, name, colors }`, `setDefaultSyntaxSet { id | null }`, `deleteSyntaxSet { id }`, and `applyPalette` whose chrome carries `syntaxColors` when the design is on a set.
- Host to webview: `library { themes, syntaxSets, hasFolder }`, re-sent when `gigglybits.library` or `gigglybits.syntaxSets` changes, `installedStarters { starters }` (each `{ id, label, extension, colors }`, from `listInstalledSyntaxStarters` in `src/themeSource.ts`), sent last on `ready` and again when extensions change, and `start { saved: { name, design } }` when the active theme is a saved theme, by its label or a retired slot label it held.
- `media/themeBuilder.js` for Start set from: `SYNTAX_SCHEMES`, `starterFromRules(rules, foreground)`, `recipeColors(id, { sw, foreground, comment, baseHue })`, `harmonyHue(frameHex, accentHex)`, `setColor`, `cleanSyntaxColors`.
- `src/themeLibrary.ts`: `themeLabel(theme)`, `companionPackage(library, sets, { version, engines, dependency, icon })`, `COMPANION_ID`; `src/companionThemes.ts`: `CompanionThemes.sync(library, sets)`; `src/vsix.ts`: `vsix(manifest, files)`.
