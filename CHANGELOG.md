# Changelog

All notable changes to GigglyBits Theme Lab are documented in this file.

## Unreleased

- **The steps say what you do in them.** Start is now **Pick your colors**, Palette is **Check readability**, Roles is **Color by purpose**, Edit is **Fine-tune a part** and Try and save is **Try it, then save**. Frame and accent keeps its name.
- **Try and save shows the palette as plain swatches.** The Fail, Large, AA and AAA tags beside each color are gone; point at a swatch for its weakest grade and pair, or see step 2 for every grade.
- **Show where shows where.** A role's **Show where** button now brings the Theme Preview window forward, opening it if it was closed, and outlines every part that role colors there, scrolled to the first. It used to open the Edit panel on the role's first color.
- **Try and save stands apart.** Its border, heading and heading line take the color of the Try in VS Code button, and it floats a little above the bottom of the Theme Lab instead of touching the edge.
- **Try and save explains itself, and lets you use a theme right after saving it.** A line under the buttons says what Try in VS Code and Save theme do. Once the design is saved (or loaded from Saved themes) and unchanged, **Use in this project** and **Use everywhere** appear beside Save theme, so you no longer go back to Start to apply it. The pinned bar is a little slimmer: the readability sentence moved into the palette's tooltip, since step 2 shows the same grades.
- **The Edit panel reads like Roles.** Each color is named in plain words with its setting name beside it ("Button background · button.background"), and shown as a sample against what it sits on instead of a dot. The heading names the part with its widget family ("Buttons: Commit"), a fully transparent color reads "transparent", and the Edits button appears only once you have edits.
- **Editing a color you clicked changes just that color.** The Edit panel now opens on **This key only**. **Whole role** is one click away and says how many colors it would change, so recoloring one button no longer recolors every accent color by surprise.
- **The Theme Preview window survives a reload properly.** After a reload or a restart, an open Theme Preview comes back with the Theme Lab, drawn and at the size and place you left it. If the Lab doesn't come back, the preview closes. Before, VS Code reopened the preview's window empty on every load, whether the Lab was open or not.
- **Roles shows each color against what it sits on.** Every role's swatch is now a small sample: a text color as "Aa" on the editor background (or on whatever it is drawn on, such as text on the accent), a fill such as Selected row with text on it, and a line such as Border as a line. Pointing at a sample says how readable it is, with its contrast ratio. The Syntax family also shows its colors as three lines of code on the editor background, and each Colors pick shows its color as the theme draws it, so you can judge syntax colors without the preview window.
- **The color picker has a Facets mode.** A Smooth / Facets switch at the top of the picker draws the hue ring as 24 flat tiles and the lightness-by-chroma panel as a grid of tiles, and a click or an arrow key lands on a tile: hue in 15 degree steps, lightness in 0.1 steps, chroma in 0.03 steps. Coarser on purpose, so picking is quick and colors land on round values. Typing a value and the lightness blocks stay exact. Every picker opens in the mode you used last.
- **Step 3 is now Frame and accent, and shows each choice before you make it.** Its rows are Frame color, Frame style, Accent and Surfaces, each with a line saying what it colors. Frame style (Filled, Dark) and Surfaces (Neutral, Tinted, Rich) are chips that each draw a small VS Code window in the colors that choice gives, so the difference between Neutral and Rich is visible, not just named. The step's heading stays short: frame, accent, surfaces, and how many accent groups have their own color.
- **The accent can be any color.** Step 3's Accent row has Custom and a color picker, like the frame. A custom accent follows the base color, and like a palette pick it also tints the surfaces. Try in VS Code, Save theme, Load and Use everywhere carry it.
- **Clearer words in Start and Palette.** Start opens with a line on how the Lab works, the tabs read Color wheel and Saved themes, and every control says what it sets when you point at it, with the scale for Lightness and Chroma. Palette's heading names the background of its weakest pair, the L C H values explain themselves, and the note under the table says a Fail there does not mean unreadable code.
- **Accent groups pick their own palette color.** Step 3 has a row for each group of colors the accent draws: Buttons, Badges and progress, Links, Selection and highlights, Focus outlines, and Cursor. Each follows the accent unless you pick one of your palette colors or a custom color, and the Lab works out that group's whole set from it (the color, its hover, the text on it and its see-through steps), lifted to stay readable. Everything else stays on the accent. While the Accent role in Roles has an edit, that edit wins over the groups, and step 3 says so. Try in VS Code, Save theme and Load carry the choices.
- **Roles says what each role colors.** Each role is one line with its color, what it is for and how many VS Code colors it draws, so a family reads as an even list. Point at a role to see the parts of the window it colors (for example Border: Popups and widgets 6, Menus and pickers 5, Lists and trees 3, and more). Open a role to change it and to see every color it draws, in plain words with the setting name beside each, in one box per part of the window. Pointing at a role, or opening it, outlines every part it colors in the Theme Preview window.
- **Try in VS Code clears an old copy of its colors that would hide it.** The Lab theme's colors belong in your user settings. If a workspace file or a folder's settings holds its own copy of them, VS Code draws that copy instead, so a Try looked like it changed nothing. Try now removes such a copy, keeps everything else in that file, and the status bar names the file it cleaned.
- **Your color edits now follow the palette.** A color you change in Roles or Edit is kept as how far you moved it from the color the palette gives (lighter or darker, more or less vivid, a turn of hue), so changing the base color or rule moves your edit with everything else. An edit to a role that draws text, such as Keywords or the accent, is still lifted to stay readable on the editor background. Under an edited color the Lab shows the color the palette gives and how far your edit moves it. A saved theme or Try with edits from before keeps its look: the Lab converts its edits when it loads them.
- **A custom frame color follows the base color too**, kept as its distance from the base, including a frame made from a folder's old color.
- **Every step collapses.** Click a step's heading to open or close it, or use **Expand all** / **Collapse all** at the top of the Theme Lab. A fresh Theme Lab opens on Start alone. Clicking a part in the Theme Preview opens step 5, Edit, and scrolls to it without opening or closing any other step. Try and save always shows.
- **Start's Wheel tab is two columns where there is room**: Base color and Rule, then Hue, Lightness and Chroma. The Rule list shows every rule's five colors at your base color, a wheel diagram of where they sit, and a line on what each rule makes, so you can compare before you pick. The sliders show their range in their tracks, Lightness and Chroma say which end is which, and the base color's hex shows beside it.
- **The Workbench preview puts the activity bar where VS Code does.** With `workbench.activityBar.location` set to top or bottom, the preview draws the activity icons as a row at that end of the side bar, in the theme's colors; set to hidden, it draws no activity bar. GigglyBits themes now set the top and bottom activity bar colors too.
- **GigglyBits themes set 127 more of the colors you see every day**, and the previews draw them: scrollbar and minimap marks, the Explorer's type-to-filter highlight, the title bar and status bar while another window has focus, symbol, snippet and hover highlights, sticky scroll, editor group drop targets, more chat colors (request bubbles, find matches, the working border) and terminal find and hover highlights. Each takes its color from a role the theme already has. Colors outside the everyday chrome, such as debugging, notebooks, merge conflicts and the agent sessions window, keep VS Code's defaults on purpose. A saved theme you already use picks the new colors up the next time you save it, use it (**Use in this project**, **Use everywhere** or **GigglyBits: Choose Theme**), or change a style group. Until then those colors come from the slot's default look.
- **The Theme Lab has its own color picker** in place of the system color dialog, at the base color, the custom frame color, a role's color and a key's color in Edit. It works in OKLCH, the space the Lab builds themes in: a hue ring around a lightness-by-chroma panel that shades the colors your screen cannot show, hex, lightness, chroma and hue fields, and five **lightness blocks** that step your color darker and lighter by 0.02, 0.05 or 0.10. The Theme Preview follows while you drag, Enter or a click outside keeps the color, and Esc puts the design back as it was. The custom frame color now previews while you drag it too.
- **The per-folder color is retired into project frames.** The Set, Next and Clear Workspace Color commands are removed, along with the `gigglybits.identity.regions` and `gigglybits.identity.offerOnOpen` settings; `gigglybits.identity.hue` and `gigglybits.identity.pinnedColor` remain only as deprecated settings. A project's color now lives in its saved theme's frame.
- A folder that still has its old color offers you, once, a project theme in that color: **Make project theme** opens the Theme Lab with that color as a Filled frame and the folder's name, **Remove the color** removes it, and **Not now** leaves it.
- **Use in this project** replaces a folder's old color with the theme's frame, without asking, and the status bar says so.
- In a Filled frame the active tab's top and bottom lines, the line between split editors and the side bar, panel and resize borders take the frame color, lifted to stay readable. Dark frames are unchanged. With VS Code's modern UI on, the active tab's top line and the side bar and panel borders are not drawn, and the background between the cards carries the frame color instead. Style groups for Tabs no longer include the two active tab lines.
- **Save theme** keeps the design you are working on as a named theme: its palette, Frame and Editor choices and color edits. Saved themes live in your user settings (`gigglybits.library`), so every VS Code window sees them and Settings Sync carries them to your other machines. Saving under a name you already used updates that theme, and every project using it changes with it. A save in one window no longer undoes a save made in another.
- **Start from > Saved** now lists your saved themes, with **Load** to bring one back exactly, **Use in this project** (with a folder open) to make it this folder's theme, frame included, **Use everywhere** to apply its Editor colors in every window with plain dark bars, so each project's frame stays its own, and **Delete**, which asks first and says projects still using it fall back to the slot's default look.
- **GigglyBits: Choose Theme** lists your saved themes by name and asks where to use the one you pick.
- **Style groups**, opened with **Edit style groups** at the foot of Start from > Saved, let you set how one kind of widget looks once and have it apply in every saved theme. Pick **Tabs**, **Lists and trees**, **Buttons** or **Editor text**, choose which theme role draws each of its colors (Raised surface, Functions, Deep surface and so on, or the theme's own), watch that family's widgets drawn alone, then name it and click **Save group**. **Back to design** puts the steps back as they were. A group you switch **On** applies to every saved theme you use, in every window, drawn from that theme's own palette, so the style is the same and the colors still differ. Only one group per family is on at a time, switching one off gives each theme its own style back, and editing a group updates every saved theme at once. A single color you edited by hand in a theme still wins over a group, and no group changes a project's frame. Try in VS Code applies the groups that are on, and the one you are building, so a Try looks like the preview. Groups live in your user settings (`gigglybits.groups`).
- VS Code's theme picker lists 12 new themes, **GigglyBits Theme 1** to **12**. Each saved theme takes one of these slots, and a slot shows its saved theme's colors once it is used. With all 12 taken, saving or using a new theme asks which one to give up its slot.
- **The Theme Lab is redesigned, with its preview in a window of its own.** Opening the Theme Lab also opens the **Theme Preview** window, a compact window of its own that is not kept on top, and it is now the only preview: one scrolling page with a **Workbench** section and a **Widgets** section, one card for each of the 23 widget families, most important first. The Lab tab is six numbered steps and a Preview card, each its own bordered card; the Preview card says whether the window is open, and **Open Preview** opens it again. On a tab at least 75rem wide (1200 px at the default font size) the Lab is two panes, steps 1 to 3 and the Try and Save bar on the left and the Preview card and steps 4 and 5 on the right; narrower, one column. Each step's heading shows its state on one line, such as `Wheel, Triad 210°` or `Frame 1 Filled · Accent 1 Neutral`. The page header, Pin, the preview tabs and the Previews box are gone; the Palette Inspector opens with its command. In the Wheel tab the base color comes first, then the rule.
- **Step 4, Roles, shows every color role, with three new settings.** The theme's 84 roles sit in the seven families the builder makes them in (Syntax, Accent, Surfaces, Text, Status, Terminal and Frame), each with a line on how it is made from your palette and its roles as buttons showing their color and how many VS Code colors use them. Click a role to change it, reset it or show where it is used. **Syntax colors** picks the palette color Keywords, Functions, Strings, Types and Numbers each use. **Surface depth** spaces the surfaces from 0.5x to 2x as far apart in lightness. **Text contrast** sets the gray text levels to Soft, Standard or High. Try in VS Code and Save theme carry all three, and a design that leaves them where they start builds exactly as before. Edit is now step 5 and Try and save step 6.
- The Edit panel has no Every role list: step 4, Roles, takes its place, and the **Roles** button on Edit's line moves there and focuses the first role.
- Step 2 is one table: each palette color with its swatch (click to copy), its L C H values, and its contrast and grade on the three reference backgrounds and your editor's. The weakest cell is outlined and named in the heading, and a line says the builder lifts syntax colors to 4.5:1 and the input outline to 3:1 on its own.
- Each cell of the step 2 table shows what it rates: the cell is a swatch of that background with "Aa" in the palette color, once at normal text size and once large and bold, beside its ratio. A color graded Large shows why: the big "Aa" stays readable where the small one fades. In the narrow left pane of the two-pane Lab, each sample sits above its ratio.
- The Workbench drawing scales to the preview window's width, never above full size.
- Clicking a part in the preview window opens the **Edit** panel in step 5: one line per color key and **Edits (n)** with Reset. Esc closes it and puts focus on the **Roles** button. On a narrow tab a pick folds steps 1 to 4 to their headings, and a pick in the title, activity or status bar brings the Frame row into the panel. A pick brings the Lab tab forward and focuses it, ready to edit. The preview window follows every change in the Lab, while you drag a color too, style groups included. The window does not come back after a window reload.
- **Start has two tabs, Wheel and Saved.** The Paste tab, with Judge pasted colors, and the Shipped theme list are gone, so you begin from a new palette or one you kept. A Lab left on Paste or Shipped opens on Wheel. A saved theme you made from pasted colors still loads, saves and tries as before. Saved themes are one line each with **Load**; the arrow beside it holds Use in this project, Use everywhere and Delete, and Enter on a line loads it.
- The Try and save step, stuck to the bottom of the steps, shows each palette color with its weakest grade, a sentence on how readable the palette is that names the colors suiting only large text or hard to read, and what it last did: **Tried in VS Code**, **Changed since your last Try**, **Saved as** the name, **Unsaved changes** or **Loaded** the name. It warns **Overwrites** before you save under another saved theme's name, and Save theme stays off while Name is empty.
- **The palette Catalog is retired.** Include, Maybe and Exclude and the list of decided palettes are gone, and saved themes take their place.
- The Theme Preview window closes when the extension stops, on a window reload or when VS Code shuts down, and a Theme Preview tab left over from before a reload is closed when the extension starts, with its window.
- **The nine named GigglyBits Dark themes are no longer included.** VS Code's theme picker lists GigglyBits Dark (Lab) and GigglyBits Theme 1 to 12 from this extension, and they look as they did. If VS Code is set to one of the nine, VS Code shows its default theme until you pick another.
- Changing the palette no longer replaces the name in Name. A name you typed, or a saved theme's name after Load, stays, so Save theme updates that theme instead of making a new one. A name nobody typed still follows the palette.
- Each Theme Lab step is its own bordered card. In the **Edit** panel, the keys sit in boxed groups (**This part**, **Around it**, and step 3's row when it is folded) with column headings, and an open key gets one color editor: **This key only** or **Whole role**, a color picker with a hex field that takes `#rrggbbaa`, an **Opacity** slider, and **Transparent**, **Use VS Code default** and **Reset**. **Use VS Code default** leaves the key out of the theme by writing `"default"` for it in your settings, which VS Code reads as "use my default".
- A folder colored by Peacock or another extension is no longer mistaken for one with an old GigglyBits folder color: the Frame row's note and the one-time project theme offer now look only at GigglyBits' own leftover, the `[GigglyBits*]` block or the deprecated pinned color. The note appears only when that block is still drawn over the frame, and names its color.
- **Try in VS Code** now shows in a workspace that sets its own theme. It used to switch only your user theme, which such a workspace overrides, so nothing changed in that window. Now it switches the workspace to GigglyBits Dark (Lab), and **Back** puts the workspace's theme back. The colors still go only to your user settings.
- The contrast numbers now explain themselves. Step 2 opens with a line saying what a contrast ratio is and that higher reads better, its columns name their backgrounds (Near black, Dark editor, Dark side bar, Your editor), and the legend says what each grade means for text. Hovering any ratio, in step 2, under the Workbench drawing, on a widget card or in the Edit panel, says what was measured and what its grade means.
- A theme now has two sets of colors, chosen in step 3. **Frame** colors the title bar, activity bar, status bar and window border: pick any palette color or your own, and a style. **Filled** gives solid colored bars with black or white text, and new designs start with it; **Dark** gives the dark bars the shipped themes have. **Editor** colors everything else: an accent color and Neutral, Tinted or Rich surfaces. Changing the Frame never moves an editor color, and in a Filled frame changing the Editor never moves the bars. Frame text reads at least 4.5:1.
- The preview is a full VS Code window, the Workbench tab, drawn with every color Try in VS Code applies, with a split editor and a chat view whose input shows its focus ring. The Code tab and its four small panels are gone.
- A Widgets tab draws the Palette Inspector's widget families (chat, buttons, inputs, lists, Command Palette, notifications, editor selection and diagnostics, and more) in the palette's colors.
- Click any part of either preview to edit the colors that draw it. Each color belongs to a role, such as Frame, Accent, Raised surface or Error. Editing a role changes every color in it and the shades made from it; This key only changes one color. Step 4, Roles, lists all the roles by family. Try in VS Code applies your Frame, Editor and color edits, and a new Theme Lab tab under the Lab theme brings them back.
- The Lab no longer previews this folder's own color. When the folder still has an old one, the Frame row says it is drawn over any theme's frame and that Use in this project replaces it.
- Input, dropdown, checkbox, panel filter and chat input outlines are brighter in every shipped theme, reading at least 3:1 against the editor and the side bar.
- The shipped themes now set the chat colors: the chat input border and background, its focus border, chat request bubbles, the slash command chip and edited-file line counts. Claude Code's chat input border follows the theme's input outline. When the input is focused, its border comes from the permission mode: the theme's error color in auto and bypass modes, its focus border in plan mode, and Claude Code's own fixed orange in default mode, which no theme can change.
- The shipped themes now color the line between split editors.
- The Palette Inspector's workbench overview gains the same split editor and chat view, and the inspector has a new Chat views card.
- The Workbench preview follows VS Code's modern UI settings. With the modern UI on (`workbench.experimental.modernUI`), it draws the side bars, editor and panel as rounded cards with gaps, and headers and panel tabs in mixed case. `workbench.experimental.modernUIUppercaseViewHeaders`, or the classic UI, brings back the capitals, and `workbench.experimental.modernUIEditorTabStyle` switches between connected and pill tabs. The floating preview window and the Palette Inspector's Workbench overview draw the same way, and every open preview redraws when one of these settings changes. The modern UI's own colors, which no GigglyBits theme sets, are worked out from the theme's colors with VS Code's default rules, and the Edit panel shows those worked-out values instead of calling the keys unset.
- The Palette Inspector's Workbench overview shrinks to fit its card instead of hiding the chat view behind a sideways scrollbar, and the empty part of the editor area in every Workbench drawing is the editor's background.

## 0.0.11

- A new Theme Lab tab now opens on the theme you are using. Under a shipped GigglyBits Dark theme, the palette starts as that theme's, exactly as if you had clicked Use, so you begin from what the window shows. Opening the Theme Lab changes no setting.
- Under GigglyBits Dark (Lab), a new Theme Lab tab reopens on your last Try in VS Code, including the chrome color and surfaces you picked. Try now records those choices in the extension's own storage; what it writes to your settings is unchanged. The palette name you typed is not restored.
- Under any other theme, or under the Lab theme before a Try has been recorded, the Theme Lab starts from the default palette and says why in a line at the top of Start from.
- In the IDE chrome preview, the workspace identity boxes now start ticked for the parts this workspace's color fills, and unticked when it has none. The preview fills them with the workspace color when there is one, instead of the chosen chrome color, and follows Use as this workspace's identity and the Set, Next and Clear Workspace Color commands while the tab is open.
- A Theme Lab tab restored by a window reload keeps the edits you had made, rather than switching to the current theme's palette.
- On start-up, a workspace color that is missing its `"[GigglyBits*]"` copy, or one of its colors, is written again, so it shows under GigglyBits themes, including the Lab theme. A complete workspace color is left alone.

## 0.0.10

- The Theme Lab is reorganized around the palette you are working on. Its colors, its lowest contrast and Try in VS Code now sit at the top, instead of below the theme list and a long column of previews.
- A new Start from column holds the four ways to begin a palette as tabs: Wheel (the harmony rule and sliders), Paste, Shipped (the installed GigglyBits Dark themes, where Use still switches the theme and loads its palette) and Saved (your decided palettes, with Load). On a narrow editor tab the column stacks above the palette instead of sitting beside it.
- The code previews, the IDE chrome preview and the full contrast table are now tabs under the palette, one at a time. The contrast table gains a legend naming the grades: 7:1 AAA, 4.5:1 AA, 3:1 large text only and under 3:1 fails.
- The tabs you choose are remembered when the Theme Lab tab reloads, and every tab set works from the keyboard with the arrow keys, Home and End.
- Try in VS Code is the only highlighted button; Include, Maybe, Exclude and Judge pasted colors are plain buttons now.
- Start from, the palette and the previews each sit in a bordered box, and the labels in each box line up in one column. In the IDE chrome tab, the workspace identity choices have their own box marked preview only, because Try in VS Code never applies them; Use as this workspace's identity does.

## 0.0.9

- Clicking Use beside a shipped GigglyBits Dark theme in the Theme Lab now also loads its palette into the Palette Lab, with the chrome color and surfaces it ships with, so you can start a new design from it. It replaces whatever candidate the Palette Lab held.
- An unchanged copy of a shipped palette cannot be saved: Include, Maybe and Exclude stay disabled with a note until you change a setting, so the shipped palette's catalog entry is never renamed by accident. A changed copy saves under the name you type, to `palettes/catalog.json`, which needs this repository's folder open.

## 0.0.8

- Added the Theme Lab, its own editor tab and the main place to build, try and pick a theme. Open it with GigglyBits: Open Theme Lab. The Palette Lab, Try in VS Code, the IDE chrome preview, Use as this workspace's identity and the saved palettes all moved there from the Palette Inspector and work as before.
- Added a theme list at the top of the Theme Lab: the installed GigglyBits Dark themes, with the active one marked. Click Use beside one to switch VS Code to it. GigglyBits Dark (Lab) is left out because it only holds what Try in VS Code last applied. When a workspace theme setting or `window.autoDetectColorScheme` overrides the switch, a notification says so.
- The Palette Inspector is now a debugging view only: the element gallery, the color breakdowns and Export as theme JSON. Each tab has a button that opens the other, and both tabs come back after a window reload.
- The publisher is now Websolete, so the extension ID changes from `edgeinformation.gigglybits-vscode-theme` to `websolete.gigglybits-vscode-theme`. VS Code sees them as two extensions: uninstall the EdgeInformation one when you install this. Your `gigglybits.*` settings carry over, since their names are unchanged, but VS Code stores the Not here choice per extension ID, so a folder where you chose Not here, or ran Clear Workspace Color, can be offered a color again: it is treated like any folder that never declined, and gets the offer if it has no workspace color of its own.

## 0.0.7

- Added workspace identity. The first time you open a trusted folder with no color of its own, a notification offers it one, derived from the folder's name: Accept colors the title bar, activity bar, status bar and tab borders, and Not here stops asking for that folder. A folder that already colors those parts, with Peacock or your own settings, gets no offer.
- Added GigglyBits: Set Workspace Color (eight suggestions or a custom hex), Next Workspace Color and Clear Workspace Color, plus the `gigglybits.identity.*` settings for the hue, a pinned color, the regions to fill and the first-open offer.
- A suggested workspace color follows the active theme: switching GigglyBits variants re-tunes its brightness and intensity and keeps its hue. A custom hex stays as entered. It shows under any theme, including Dark Modern and the Lab theme, without erasing a Lab design.
- The Palette Lab's IDE chrome preview has a Use as this workspace's identity button that sets the previewed color as the workspace color. Try in VS Code no longer writes workspace settings: the identity checkboxes only preview. A folder where 0.0.6's Try wrote identity colors keeps them and gets no offer; run Clear Workspace Color or Set Workspace Color there once.
- Fixed the Palette Inspector naming your preferred dark theme (such as Dark 2026) instead of the theme on screen. It read the high-contrast auto-detect setting, which is on by default, as if it applied to every theme.

## 0.0.6

- Added an IDE chrome preview to the Palette Lab, below the code previews: a miniature VS Code window (title bar, activity bar, side bar, tabs, editor, panel, status bar) drawn from one palette color you pick. The Neutral surfaces match what the GigglyBits Dark variants ship; Tinted and Rich carry the color's hue into the bars, side bar and tabs.
- Tick Title bar and window border, Activity bar, Status bar, or Tabs and borders to try a per-workspace identity color, the way Peacock does, with black or white text chosen for contrast and readouts for each bar. Copy workspace overlay copies the matching `workbench.colorCustomizations` block for a workspace's `.vscode/settings.json`.
- Added Try in VS Code to the Palette Lab. It applies the current candidate, with its chrome color, surfaces and identity regions, as the new GigglyBits Dark (Lab) theme without a reload. The colors go into your user settings scoped to that theme, so other themes are untouched, and the identity regions go into the workspace settings in place of Peacock's colors. The confirmation offers to switch back to your previous theme.

## 0.0.5

- Renamed the extension from GigglyBits Theme to GigglyBits Theme Lab. Its ID, commands and theme names are unchanged.
- Added the GigglyBits Dark color themes: one per palette marked Include in the Palette Lab, named after the palette, such as GigglyBits Dark (Candy). Pick one with Preferences: Color Theme.
- Every variant draws the editor on #1e1e1e. Palette colors too dark to read as text are lightened, keeping their hue, until they read at 4.5:1, and colors that end up too alike are pushed apart.
- The variants give code only broad baseline colors and set no semantic token rules, so coloring from your specialized extensions still wins.
- Every part of VS Code the element gallery draws gets its color from the theme, apart from six keys left unset on purpose, such as the high-contrast borders.
- Added a base color picker beside the Palette Lab sliders: pick a color and its hue, lightness and chroma fill the sliders; move a slider and the picker follows.
- Added the GigglyBits logo as the extension's Marketplace and Extensions view icon.

## 0.0.4

- Added the Palette Lab to the Palette Inspector, below the element gallery: build five-color candidate palettes from a base hue with eight color-wheel harmony rules (Analogous, Monochromatic, Triad, Complementary, Split Complementary, Square, Compound, Shades), computed in OKLCH and kept inside sRGB without shifting lightness or hue.
- Paste a list of hex values, for example from Adobe Color, to judge a palette from elsewhere. Tokens that are not colors are named rather than dropped silently.
- Each candidate shows its contrast against three dark reference backgrounds and your current editor background, and a preview of it on code, a button, a badge, a focus ring and a selection on each of those backgrounds.
- Mark a candidate Include, Maybe or Exclude, with a name and a note. Decisions are saved to `palettes/catalog.json` in the first open folder, replacing any earlier decision on the same palette, and the saved list can load one back. Without an open folder the decision buttons are disabled and say why.

## 0.0.3

- Added an element gallery at the top of the Palette Inspector: buttons, inputs, lists, tabs, the editor, widgets, menus, notifications, the status bar, the terminal and more, drawn with the colors in effect and with each state side by side. Hover a part to see the color keys that draw it; open Definitions for each key's value, source, contributing extension and contrast.

## 0.0.2

- Fixed `GigglyBits: Open Palette Inspector` failing with "command not found" in the installed extension.

## 0.0.1

- Added `GigglyBits: Open Palette Inspector`, an editor tab that lists every workbench color in effect, grouped by area, with the source of each one (theme, user override or VS Code default) and a contrast ratio for text colors.
- The inspector also lists the theme's syntax and semantic token rules on sample text, flags color keys that are declared but have no effect, and can export everything in effect as a starting theme file.
